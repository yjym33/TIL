: React로 서버 관리

# 쿼리 생성 및 상태

## React Query

- 클라이언트에서 서버 데이터 캐시를 관리
- React 코드에 서버 데이터가 필요할 때, 페치(Fetch)나 Axios를 사용해 서버로 바로 이동하지 않고,
  React Query 캐시를 요청
- React Query 클라이언트를 어떻게 구성했느냐에 따라 해당 캐시의 데이터를 유지 관리
- React Query : 데이터의 관리
  사용자 : 서버의 새 데이터로 캐시를 업데이트하는 시기를 설정
- 기능
  - 서버에 대한 모든 쿼리의 오류 및 로딩 상태를 유지
  - 페이지 매김, 무한 스크롤이 필요한 경우, 데이터를 조각으로 가져올 수 있는 도구 제공
  - 데이터를 미리 가져와서 캐시에 넣어둘 수 있음 (Prefetching)
  - 데이터의 변이나 업데이트를 관리 (Mutation)
  - 중복 요청 제거 (De-duplication of requests)
  - 서버에서 오류나는 경우, 재시도 요청 가능
  - 쿼리가 성공했거나 오류났을 때를 구분하여 콜백 전달 가능
- 본 강의는 CSR. ([SSR과의 차이점 및 고려해야 할 점 참고 문서](https://tanstack.com/query/latest/docs/framework/react/guides/ssr))
- 라이브러리 설치
  ```powershell
  npm install @tanstack/react-query
  ```

## 쿼리 클라이언트

- 쿼리, 캐시, 쿼리 캐시를 조작하는 도구 → 직접 사용 X
- 쿼리클라이언트를 속성으로 쓰는 `QueryClientProvider(공급자)` 추가
  → 공급자의 자식들은 캐시를 포함한 쿼리클라이언트에 접근 가능

  - app.jsx

    ```jsx
    ...
    import { QueryClient, QueryClientProvider } from "@tanstack/react-query";
    const queryClient = new QueryClient();

    function App() {
    	return (
    	  <QueryClientProvider client={queryClient}>
    	    <Component {...pageProps} />
    	  </QueryClientProvider>
    	);
    }

    export default App;
    ```

## useQuery

[docs : useQuery](https://tanstack.com/query/latest/docs/framework/react/reference/useQuery)

- 서버에서 데이터를 검색하고, 최신 상태를 유지

```jsx
const data = useQuery({
  queryKey: ["posts"],
  queryFn: fetchPosts,
});

if (!data) {
  return <div />;
}
```

- 옵션
  - queryKey : 쿼리 캐시 내의 데이터를 정의. 항상 배열(react-query version4 이상)
  - queryFn : 데이터를 가져오기 위해 실행할 함수
  - 기본적으로 재시도 3번

## 로딩∙에러 상태 처리

[docs: Query Retries](https://tanstack.com/query/latest/docs/framework/react/guides/query-retries)

```jsx
const { data, isLoading, isError, error } = useQuery({
  queryKey: ["posts"],
  queryFn: fetchPosts,
});

if (isLoading) {
  return <h3>Loading...</h3>;
}
if (isError) {
  return (
    <>
      <h3>Error...</h3>
      <p>{error.toString()}</p>
    </>
  );
}
```

- isFetching
  - 비동기 쿼리 함수가 아직 해결되지 않았을 때 true = 데이터를 아직 가져오고 있는 상태
  - Axios 호출이나 GraogQL 호출 같은 다른 종류의 데이터를 가져오는 작업일 수 있다.
- isLoading
  - isFetcing의 하위 집합으로, 로딩 중을 의미
  - 쿼리 함수가 아직 미해결이지만, 캐시된 데이터도 없다.
    = 해당 쿼리에 대한 캐시된 데이터가 없는 상태
  - 이 쿼리를 전에 실행한 적이 없어서 데이터를 가져오는 중

## React Query 개발자 도구

[docs: React Devtools](https://tanstack.com/query/latest/docs/framework/react/devtools)

  → 디버깅에 좋음


- `npm run dev` 로 실행시 아래 야자수 아이콘으로 접근 가능
- Data Explorer : queryFn으로 가져온 데이터 볼 수 있음
- Query Explorer
  - queryKey : 하나의 항목이 있는 배열
  - gcTime : 가비지 컬렉션 시간과 관련된 해당 쿼리의 리액트-쿼리 내부 상태

### staleTime

- staleTime = 데이터의 최대 수명 (기본으로는 0ms)
- 데이터를 다시 가져와야 할 때를 알려준다.
- 자동으로 prefetch 되는 경우
  - 쿼리를 포함하는 컴포넌트가 다시 마운트
  - 브라우저 창이 리포키싱
  - stale 상태에서만 prefetch가 가능하다.
- useQuery 옵션에서 설정
  ```jsx
  const { data, isLoading, isError, error } = useQuery({
    queryKey: ["posts"],
    queryFn: fetchPosts,
    staleTime: 2000,
  });
  ```
  → 2초(=2000ms)동안 fresh 상태였다가 stale로 변경됨
  (데이터가 fresh할 때는 refetch 트리거가 발생해도 데이터를 다시 가져오지 않음)
- stale 상태이고 서버에 캐시된 데이터가 있으면,
  서버에서 최신 버전의 데이터를 가져올 때까지 캐시된 데이터를 보여준다.

### gcTime

- 데이터를 캐시에 유지할 시간을 결정 (기본 5분)
- 데이터와 연관된 활성 useQuery가 없고 데이터가 현재 페이지에 표시되지 않으면 쿨 스토리지 상태로 들어가는데, 쿼리가 캐시에 있으나 사용되진 않고 유효기간(=gcTime)이 정해져 있다.
- 데이터가 페이지에 표시된 후부터 시간이 측정된다.
- 데이터가 페이지에 표시될 때는 진행되지 않는다.
  하지만 데이터가 React에서 더 이상 사용되지 않으면 진행된다.

# 프리페칭과 변이

## queryKey

- queryKey로 클라이언트의 데이터가 서버의 데이터와 다르다고 알게 된다.
  - 컴포넌트를 다시 마운트
  - 창에 다시 포커싱
  - useQuery에서 반환된 Refetch 함수를 수동으로 실행
  - 지정된 간격에서 자동으로 재검색
  - 변형 후 쿼리를 무효화
- 각 쿼리는 개별적인 stale시간과 개별적인 캐시 시간을 갖는다. → queryKey(종속성 배열)로 구분
- 데이터를 가져올 때 쓰는 쿼리 함수의 모든 값은 키의 일부여야 한다.

```jsx
const { data, isLoading, isError, error } = useQuery({
  queryKey: ["comments", post.id],
  queryFn: () => fetchComments(post.id),
});
```

⇒ 화면에 보이지 않는 데이터들은 비활성 상태(0)로 들어가고 gc시간이 진행된다.

## Pre-fetching

[docs: **prefetchQuery & prefetchInfiniteQuery**](https://tanstack.com/query/latest/docs/framework/react/guides/prefetching#prefetchquery--prefetchinfinitequery)

- 데이터를 캐시에 추가
- 데이터는 기본적으로 stale로 간주
  → 새로고침 될 때까지 캐시에 있는 데이터를 표시 (캐시가 만료되지 않았을 때)
- pagination 등 여러 곳에서 사용
- pagination prefetching

  ```jsx
  import { useQuery, useQueryClient } from "@tanstack/react-query"
  ...
    const queryClient = useQueryClient();

    useEffect(() => {
      if(currentPage < maxPostPage) {
        const nextPage = currentPage + 1;
        queryClient.prefetchQuery({
          queryKey: ["posts", nextPage],
          queryFn: () => fetchPosts(nextPage),
        });
      }
    }, [currentPage, queryClient]);

    const { data, isLoading, isError, error } = useQuery({
      queryKey: ["posts", currentPage],
      queryFn: () => fetchPosts(currentPage),
      staleTime: 2000
    });
  ```

## useMutation

[docs: Mutations](https://tanstack.com/query/latest/docs/framework/react/guides/mutations)

- 서버에 네트워크 호출해 서버에서 실제 데이터를 업데이트 (추가, 삭제, 변경 등)
- mutation 사용시 데이터 표시 방법
  - 낙관적 업데이트 : 서버 호출이 잘될 거라 가정하고 잘 안됐을 경우, 되돌림
  - 서버에서 데이터 수신 (Mutation 호출할 때 업데이트된 데이터를 수신)
  - 관련 쿼리 무효화
- useQuery와 비교했을 때 useMutation의 특징
  - `mutate` 함수(서버에 변경 사항을 호출할 떄 사용)를 반환
  - queryKey를 사용하지 않음 → 데이터 저장 X
  - isFetching 없음 (캐시된 것잉 없어서 의미 X) → 변이와 관련된 캐시 없음
  - 기본적으로 재시도 없음

```jsx
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query"
...
const deleteMutation = useMutation({
  mutationFn: (postId) => deletePost(postId)
});
  const updateMutation = useMutation({
    mutationFn: (postId) => updatePost(postId)
  })
...
deleteMutation.reset();
updateMutation.reset();
...
<button onClick={() => deleteMutation.mutate(post.id)}>Delete</button>
{deleteMutation.isPending && (
  <p className="loading">Deleting the post</p>
)}
{deleteMutation.isError && (
  <p className="error">Error post : {deleteMutation.error.toString()}</p>
)}
{deleteMutation.isSuccess && (
  <p className="success">Post was (not) deleted</p>
)}
...
```

## useInfiniteQuery 입문

[docs: useInfiniteQuery](https://tanstack.com/query/latest/docs/framework/react/reference/useInfiniteQuery)

[docs: **Infinite Queries**](https://tanstack.com/query/latest/docs/framework/react/guides/infinite-queries)

- 사용자가 페이지의 특정 지점에 도달하거나 버튼을 클릭할 때, 더 많은 데이터를 로딩하는 리액트-쿼리
- 반환되는 객체가 data와 pages라는 두 가지 속성을 포함
  - pages : 각 데이터 페이지를 나타내는 객체의 배열
  - pageParams
    - 잘 사용되지 않음
    - 각 페이지마다 사용하는 파라미터를 기록 → 검색된 쿼리 키 추적
    - 쿼리 함수에 전달되는 매개변수
      → 각 쿼리는 pages 배열의 자신만의 요소(해당 쿼리의 데이터를 나타낸다.)를 가지고 있다.
      cf) useQuery : 쿼리 함수에서 데이터가 data속성에 담겨 반환
- fetchNextPage : 사용자가 더 많은 데이터를 필요할 때마다 호출하고 싶은 함수
- hasNextPage
  - getNextPageParam 함수의 반환 값에 기반
  - useInfiniteQuery에 전달하는 속성은 마지막 쿼리의 데이터를 사용해 다음 쿼리가 뭐가 될지 알려주는 속성
    이 속성이 undefined이면 더 이상 데이터가 없다. → hasNextPage는 false
- isFetchingNextPage
  - 다음 페이지를 가져오는 중인지 일반적으로 데이터를 가져오는 중인지 구별 가능

## diagram

```jsx
useInfiniteQuery({
	queryKey: ["sw-people"],
	queryFn: ({ pageParam = initialUrl }) => fetchUrl(pageParam),
	getNextPageParam: (lastPage, allPages) => ...
});
```

1. 컴포넌트 마운트 (현재 시점에서 useInfiniteQuery에서 반환된 객체의 데이터 속성은 undefined)
2. useInfiniteQuery가 쿼리함수를 사용해 첫 페이지를 수신
3. 리액트-쿼리가 getNextPageParam을 실행
   getNextPageParam : 마지막 페이지와 모든 페이지를 받아 pageParam을 업데이트
4. hasNextPage 존재 판별
5. 유저가 스크롤하거나 버튼을 클릭한경우 fetchNextPage 호출
   fetchNextPage : useInfiniteQuery이 반환하는 객체의 속성
6. 데이터 수신 후, 다음 페이지 매개변수 설정을 위해 getNextPageParam 실행

## InfiniteScroll 컴포넌트

[docs: **React Infinite Scroller**](https://www.npmjs.com/package/react-infinite-scroller)

- 무한 스크롤 컴포넌트 필요 속성
  - hasMore : 로딩할 데이터 더 있는지 여부
    = hasNextPage : 무한 스크롤에서 반환된 객체에서 구조 분해 가능
  - loadMore : 무한 스크롤러가 더 많은 데이터를 로딩할 때 실행되는 함수

```jsx
export function InfinitePeople() {
  const { data, fetchNextPage, hasNextPage, isFetching, isLoading } =
    useInfiniteQuery({
      queryKey: ["sw-people"],
      queryFn: ({ pageParam = initialUrl }) => fetchUrl(pageParam),
      getNextPageParam: (lastPage) => {
        return lastPage.next || undefined;
      },
    });

  if (isLoading) {
    return <div className="loading">Loading...</div>;
  }

  return (
    <>
      {isFetching && <div className="loading">Loading...</div>}
      <InfiniteScroll
        loadMore={() => {
          if (!isFetching) {
            fetchNextPage();
          }
        }}
        hasMore={hasNextPage}
        initialLoad={false}
      >
        {data.pages.map((pageData) => {
          return pageData.results.map((person) => {
            return (
              <Person
                key={person.name}
                name={person.name}
                hairColor={person.hair_color}
                eyeColor={person.eye_color}
              />
            );
          });
        })}
      </InfiniteScroll>
    </>
  );
}
```

## 쿼리 클라이언트의 onError

- 리액트 쿼리는 중앙 집중식 훅대신 쿼리 캐시에 대해 설정할 수 있는 onError 콜백을 제공
  → queryClient를 생성할 때, 쿼리 캐시의 기본값 (queryCache를 추가한 후 오류 콜백 추가 가능)
- 오류 콜백은 useQuery에서 발생하는 오류에 관계없이 전달되며,
  콜백 본문 내에서 오류 처리 가능

```jsx
import { toast } from "@/components/app/toast";
import { QueryCache, QueryClient } from "@tanstack/react-query";

function errorHandler(errorMsg: string) {
  const id = "react-query-toast";

  if (!toast.isActive(id)) {
    const action = "fetch";
    const title = `could not ${action} data: ${
      errorMsg ?? "error connecting to server"
    }`;
    toast({ id, title, status: "error", variant: "subtle", isClosable: true });
  }
}

export const queryClient = new QueryClient({
  queryCache: new QueryCache({
    onError: (error) => {
      errorHandler(error.message);
```

## 데이터 필터링

[blog: React Query Data Transformations](https://tkdodo.eu/blog/react-query-data-transformations)

- 쿼리 함수에서 반환되는 데이터를 변환
- 데이터가 변경되거나 함수가 변경된 경우에만 선택함수를 실행 → 최적화
  → 매번 변경되는 익명 함수를 사용할 수 없다.

```jsx
const queryClient = useQueryClient();
useEffect(() => {
  const nextMonthYear = getNewMonthYear(monthYear, 1);
  queryClient.prefetchQuery({
    queryKey: [queryKeys.appointments, nextMonthYear.year, nextMonthYear.month],
    queryFn: () => getAppointments(nextMonthYear.year, nextMonthYear.month),
  });
}, [queryClient, monthYear]);

const { userId } = useLoginData();

const selectFn = useCallback(
  (data: AppointmentDateMap, showAll: boolean) => {
    if (showAll) return data;
    return getAvailableAppointments(data, userId);
  },
  [userId]
);

const fallback: AppointmentDateMap = {};

const { data: appointments = fallback } = useQuery({
  queryKey: [queryKeys.appointments, monthYear.year, monthYear.month],
  queryFn: () => getAppointments(monthYear.year, monthYear.month),
  select: (data) => selectFn(data, showAll),
});
```

- prefetch는 데이터를 캐시에 저장하고 useQuery가 호출되면 데이터를 변환하고 필터링
  → prefetch에서 select를 할 필요 없다.

  ```jsx
  import { act, renderHook, waitFor } from "@testing-library/react";

  import { useAppointments } from "../hooks/useAppointments";
  import { AppointmentDateMap } from "../types";

  import { createQueryClientWrapper } from "@/test-utils";

  const getAppointmentCount = (appointments: AppointmentDateMap) =>
    Object.values(appointments).reduce(
      (runningCount, appointmentsOnDate) =>
        runningCount + appointmentsOnDate.length,
      0
    );

  test("filter appointments by availability", async () => {
    const { result } = renderHook(() => useAppointments(), {
      wrapper: createQueryClientWrapper(),
    });

    console.log(result);

    //목 서비스워커를 통한 네트워크 호출을 포함하므로 비동기적으로 진행된다.
    await waitFor(() =>
      expect(getAppointmentCount(result.current.appointments)).toBeGreaterThan(
        0
      )
    ); //→ 서버에서 데이터를 받기 전에 예약을 세는 것이 아니라 실제 예약 수를 얻을 수 있다.

    // show only available
    const filteredAppointmentsLength = getAppointmentCount(
      result.current.appointments
    );
    act(() => result.current.setShowAll(true)); // 실시간으로 업데이트 (훅의 반환값이 업데이트)

    await waitFor(() =>
      expect(getAppointmentCount(result.current.appointments)).toBeGreaterThan(
        filteredAppointmentsLength
      )
    );
  });
  ```
